# 关卡并行开发指南

## 并行开发边界

每位开发者只修改自己的 `src/levels/<关卡标识>/` 和对应的
`tests/levels/`。关卡之间禁止互相导入，普通关卡开发不得修改以下共享目录：

- `src/game.js`
- `src/runtime/`
- `src/systems/`
- `src/ui/`
- `src/world/`
- `src/config/`

如果新增关卡需要修改这些目录，说明需求属于共享协议变更，必须先单独评审和合并，
再由各关卡分支使用新协议。不要在共享代码中添加关卡标识判断。

可复制的最小样例位于 `tests/fixtures/sample-level/`。正式关卡建议保持以下文件：

- `definition.js`：元数据、动作声明、扩展注册。
- `createLevel.js`：规则、状态与生命周期。
- `actors.js`：玩家和非玩家角色外观。
- `world.js`：场景搭建。
- `preview.js`：选关页目标预览。
- `animations.js`：关卡角色的可选动画。
- `view.js`：关卡专属弹层内容和显示逻辑。
- `audio.js`：关卡专属音效入口。
- `styles.css`：关卡专属主题、弹层和选关卡片样式。
- `constants.js`：只属于该关卡的数值。

关卡样式由注册中心自动加载，不要把关卡选择器写入 `src/styles.css`。

## 稳定能力接口

`createLevel.js` 只能使用冻结的分组上下文：

- `time`：游戏阶段和累计时间。
- `actors`：创建、查询、移动和销毁角色。
- `movement`：寻路、朝向和碰撞查询。
- `combat`：命中、震动、顿帧和关卡结算。
- `ui`：动态弹层、主题和抬头信息刷新。
- `audio`：共享音效播放入口。
- `random`：统一随机数能力。
- `sceneData`：本关卡 `world.js` 返回的场景资源。

不要读取已经废弃的扁平字段，也不要把关卡私有对象挂到共享会话上。

## 新增步骤

1. 复制样例目录到 `src/levels/<关卡标识>/`。
2. 完成 `definition.js`。注册中心会自动发现，无需修改注册表。
3. 将样例角色工厂替换为本关卡的真实角色工厂。
4. 只声明实际处理的 `actions`；未知动作会在校验时直接失败。
5. 通过 `extensions` 提供场景、角色和预览能力。
6. 将专属场景资源从 `world.js` 返回，通过 `context.sceneData` 使用。
7. 在 `tests/levels/` 增加规则、场景和扩展测试。
8. 执行 `npm test` 和 `npm run build`。

## 需要协调的改动

只有新增全局动作、扩展点或通用引擎能力时，才修改 `actions.js`、
`levelContract.js` 或共享运行时。推荐流程：

1. 先提交最小协议变更和协议测试。
2. 协议合并后，各关卡分支同步最新代码。
3. 各关卡仅在自己的目录中实现协议。
4. 禁止多个关卡分支同时修改同一个共享模块。

架构测试会自动检查：

- 关卡之间没有互相导入。
- 共享运行时没有具体关卡名称或专属角色特征。
- 全局样式没有关卡专属选择器。
- `game.js` 只保留启动出口。
- 核心共享模块没有重新膨胀为超大文件。

双人决斗已保存在 `src/modes/duel/`，属于未启用的独立模式。单人关卡不得依赖或导入该目录。
