# 关卡并行开发指南

## 目录边界

每个关卡只修改 `src/levels/<关卡标识>/` 和对应的 `tests/levels/` 测试文件。关卡之间禁止互相导入，也不要在 `game.js`、角色工厂、场景构建器或界面代码中按关卡标识增加条件分支。

可复制的最小样例位于 `tests/fixtures/sample-level/`。正式关卡建议保持以下文件：

- `definition.js`：元数据、动作声明、扩展注册。
- `createLevel.js`：规则、状态与生命周期。
- `actors.js`：玩家和非玩家角色外观。
- `world.js`：场景搭建。
- `preview.js`：选关页目标预览。
- `constants.js`：只属于该关卡的数值。

## 新增步骤

1. 复制样例目录到 `src/levels/<关卡标识>/`。
2. 完成 `definition.js`。注册中心会自动发现，无需修改注册表。
3. 只声明实际处理的 `actions`；拼写错误会在校验时直接失败。
4. 通过 `extensions` 提供场景、角色和预览能力；共享运行时不识别关卡类型。
5. 在 `tests/levels/` 增加本关卡测试，执行 `npm test` 和 `npm run build`。

## 需要协调的改动

只有新增全局动作、扩展点或通用引擎能力时，才修改 `actions.js`、`levelContract.js` 或共享运行时。这类改动先约定契约，再由一人完成；普通关卡开发不应触碰这些文件。

双人决斗已保存在 `src/modes/duel/`，属于未启用的独立模式。单人关卡不得依赖或导入该目录。
