# 关卡并行开发指南

## 并行开发边界

每位开发者只修改自己的 `src/levels/<关卡标识>/` 和对应的
`tests/levels/`。关卡之间禁止互相导入，普通关卡开发不得修改以下共享目录：

- `src/main.js`
- `src/runtime/`
- `src/systems/`
- `src/ui/`
- `src/world/`
- `src/config/`

如果新增关卡需要修改这些目录，说明需求属于共享协议变更，必须先单独评审和合并，
再由各关卡分支使用新协议。不要在共享代码中添加关卡标识判断。

项目支持两种关卡：

- 经典内容关卡：复用现有俯视角移动、角色、战斗和抬头界面，样例位于
  `tests/fixtures/sample-level/`。
- 独立玩法关卡：自行实现玩法循环、输入、镜头和隔离界面，样例位于
  `tests/fixtures/standalone-level/`。

先确定关卡类型，再复制对应样例。不要为了实现独立玩法去修改经典系统。

所有关卡都在 `definition.js` 声明剧情归属：

- 人生主线使用 `track: "mainline"`，并声明唯一的正整数 `age`。
- 番外关卡使用 `track: "extra"`，不声明 `age`。
- `order` 决定选关顺序；新增主线应预留间隔，避免其他分支同时改已有顺序。
- `transition.intro` 是进入本年龄阶段的衔接文案，
  `transition.success` 是通关后通向下一阶段的文案。

主线由进度模块自动逐关解锁，番外始终开放。关卡内部不得直接读取或修改主线存档。

经典内容关卡建议保持以下文件：

- `definition.js`：元数据、动作声明、扩展注册。
- `createLevel.js`：规则、状态与生命周期。
- `actors.js`：玩家和非玩家角色外观。
- `world.js`：场景搭建。
- `preview.js`：选关页目标预览。
- `animations.js`：关卡角色的可选动画。
- `view.js`：关卡专属弹层内容和显示逻辑。
- `audio.js`：关卡专属音效入口。
- `styles.css`：关卡专属主题和弹层样式。
- `constants.js`：只属于该关卡的数值。

选关卡片颜色写入 `definition.cardStyle`。关卡样式由注册中心读取为文本，只在当前
关卡生命周期内安装，不要把关卡选择器写入 `src/styles.css`。

## 经典内容关卡接口

`createLevel.js` 只能使用冻结的分组上下文：

- `time`：游戏阶段和累计时间。
- `actors`：创建、查询、移动和销毁角色。
- `movement`：寻路、朝向和碰撞查询。
- `combat`：命中、震动、顿帧和关卡结算。
- `ui`：动态弹层、主题和抬头信息刷新。
- `audio`：共享音效播放入口。
- `random`：统一随机数能力。
- `sceneData`：本关卡 `world.js` 返回的场景资源。

不要读取已经废弃的扁平字段，也不要把关卡私有对象挂到共享会话上。

## 独立玩法关卡接口

独立关卡不提供 `createLevel`，只在 `extensions` 中注册
`createExperience(host)`。体验对象必须实现：

- `mount()`：创建本关卡界面和资源。
- `start()`：进入可操作状态。
- `update(deltaSeconds)`：更新自己的规则和状态。
- `dispose()`：释放关卡自己持有的资源。

可选实现 `pause()`、`resume()`、`handleInput()`、`render()`、
`updateResult()`、`getResultStats()` 和 `showResult()`。

独立关卡只能使用宿主提供的能力：

- `surface`：隔离根节点中的界面内容和样式。
- `input`：随关卡资源域自动解绑的事件监听。
- `rendering`：画布、渲染器、场景和自定义镜头。
- `flow`：开始、暂停、继续、结算和离开。
- `audio`：共享音效入口。
- `storage`：自动按关卡标识隔离的存储。
- `time`、`random`：阶段、累计时间和随机数。

独立关卡内部动作由自己的体验对象处理，不需要登记到中央 `actions.js`。

## 新增经典内容关卡

1. 复制样例目录到 `src/levels/<关卡标识>/`。
2. 完成 `definition.js`。注册中心会自动发现，无需修改注册表。
3. 将样例角色工厂替换为本关卡的真实角色工厂。
4. 只声明实际处理的 `actions`；未知动作会在校验时直接失败。
5. 通过 `extensions` 提供场景、角色和预览能力。
6. 将专属场景资源从 `world.js` 返回，通过 `context.sceneData` 使用。
7. 在 `tests/levels/` 增加规则、场景和扩展测试。
8. 执行 `npm test` 和 `npm run build`。

## 新增独立玩法关卡

1. 复制 `tests/fixtures/standalone-level/` 到
   `src/levels/<关卡标识>/`。
2. 在 `definition.js` 中设置元数据、`cardStyle`，并注册
   `extensions.createExperience`。
3. 在 `createExperience.js` 内完成玩法状态和生命周期，不导入经典系统。
4. 在 `mount()` 的开始界面中调用 `host.flow.start()` 进入正式游戏。
5. 所有事件通过 `host.input.listen()` 登记，所有界面写入
   `host.surface`。
6. 自定义三维玩法通过 `host.rendering` 创建自己的场景和镜头。
7. 使用 `host.flow.finish()` 结算，使用 `host.flow.leave()` 返回选关。
8. 在自己的关卡目录内维护样式、资源和辅助模块。
9. 增加完整生命周期测试，并执行 `npm test` 和 `npm run build`。

## 手机横屏约束

- 游戏进行中竖屏会由共享方向控制器暂停；关卡无需自行监听屏幕方向。
- 所有触控监听必须通过 `host.input.listen()` 注册，暂停时要释放关卡内的指针状态。
- 独立关卡的界面要使用安全区域变量，并为横屏矮视口提供紧凑布局。
- 操作按钮需设置 `touch-action`，不能依赖鼠标悬停才能理解或操作。
- 结算页的离开操作统一写作“返回人生时间线”。

## 需要协调的改动

只有新增全局动作、扩展点或通用引擎能力时，才修改 `actions.js`、
`levelContract.js` 或共享运行时。推荐流程：

1. 先提交最小协议变更和协议测试。
2. 协议合并后，各关卡分支同步最新代码。
3. 各关卡仅在自己的目录中实现协议。
4. 禁止多个关卡分支同时修改同一个共享模块。

架构测试会自动检查：

- 关卡之间没有互相导入。
- 共享运行时没有具体关卡名称或专属角色特征。
- 全局样式没有关卡专属选择器。
- 注册中心不会把所有关卡样式全局注入。
- 独立玩法样例没有引用经典玩法系统。
- `main.js` 只保留启动出口。
- 核心共享模块没有重新膨胀为超大文件。

双人决斗链路已删除。若后续恢复联机玩法，请重新作为独立模式实现，不要接回单人关卡目录。
