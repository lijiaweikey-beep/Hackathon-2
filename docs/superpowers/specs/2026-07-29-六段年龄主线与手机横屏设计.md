# 《梗哥的半生》六段年龄主线与手机横屏设计

> 日期：2026-07-29
>
> 状态：已确认

## 1. 目标

把现有选关集合重组为一条按年龄推进的人生主线：

1. 19 岁：宿舍凌晨三点。
2. 21 岁：图书馆亲嘴情侣。
3. 23 岁：夜市辨认卖鹅腿的阿姨。
4. 25 岁：超市潜行取证。
5. 27 岁：办公室躲黑锅并找到老板。
6. 30 岁：冲压机爆金币还贷。

“承天寺夜游”和“血月街区”继续保留，但移动到番外入口，不参与主线解锁和结局判定。

游戏必须能在手机浏览器中横屏游玩。竖屏时暂停当前体验并显示旋转提示，恢复横屏后继续。

## 2. 产品流程

### 2.1 入口

选关界面分为两个入口：

- 人生主线：显示六个年龄节点。
- 番外关卡：显示承天寺夜游和血月街区。

番外不显示年龄，不改变主线完成度，不受主线锁定状态影响。

### 2.2 解锁

- 初始仅解锁 19 岁。
- 通关当前最远关卡后，解锁紧邻的下一年龄节点。
- 已通关关卡始终可以重玩。
- 失败不会解锁下一关。
- 本机保存每个已通关关卡的标识，不只保存一个数字进度，避免关卡调整顺序后错误解锁。
- 存档缺失、损坏或包含未知关卡标识时，忽略无效值并保证第一关可玩。

测试模式是唯一例外：

- 本地开发环境自动进入测试模式，六个主线关卡全部直接开放。
- 测试人员无需通关前置关卡，也无需逐个手动解锁。
- 测试模式只跳过入口锁定，不伪造通关记录，不显示主线终章。
- 正式构建继续执行上述逐关解锁规则。

### 2.3 关卡衔接

完整流程为：

```text
人生时间线
→ 年龄开场
→ 关卡
→ 成功或失败结算
→ 成功时显示阶段收束文案
→ 返回人生时间线
→ 点亮下一年龄节点
```

30 岁通关后显示六阶段回顾和主线结局。失败结算提供重试与返回时间线；成功结算返回时间线，不自动闯入下一关。

## 3. 架构

### 3.1 元数据驱动分组

每个关卡在自身 `definition.js` 中声明：

- `track`：`mainline` 或 `extra`。
- `age`：主线年龄，番外不提供。
- `order`：当前分组内顺序。
- `transition`：本阶段开场、成功收束和结局回顾所需的短文案。

注册中心只校验和排序元数据。共享界面根据元数据渲染，不出现 `gaming`、`library` 等具体关卡标识判断。

### 3.2 关卡类型

前三关属于经典内容关卡，复用移动、角色、攻击、镜头和通用抬头界面：

- `gaming`
- `library`
- 新增 `goose-market`

后三关属于独立玩法关卡，通过 `extensions.createExperience(host)` 管理自己的状态、界面和生命周期：

- 新增 `supermarket`
- 新增 `office`
- 新增 `debt-smasher`

独立玩法不得导入经典玩法系统。关卡之间不得互相导入。共享层不添加具体关卡标识分支。

### 3.3 文件边界

共享改动限定为：

- 关卡元数据协议。
- 主线进度存储。
- 人生时间线与番外分组界面。
- 方向检测、暂停协调和手机安全区域。

每个新增关卡只在 `src/levels/<关卡标识>/` 中维护世界、角色、规则、样式和体验对象；测试放在对应的 `tests/levels/` 文件中。

## 4. 关卡设计

### 4.1 19 岁与 21 岁

保留现有宿舍和图书馆实现，补充主线元数据、年龄开场和阶段收束文案。图书馆仍以亲吻后的口红印作为核心线索。

### 4.2 23 岁：鹅腿夜市

- 夜间学校外墙和两侧路灯组成辨认场景。
- 19～24 名阿姨携带外形一致的鸭腿或鹅腿随机移动。
- 路灯以移动锥形光区扫过人群。
- 鸭腿进入灯光后出现微弱绿色轮廓，鹅腿不发光。
- 身体遮挡会暂时挡住光效，玩家需结合多个照明时机确认目标。
- 找到卖鹅腿的阿姨并一拳命中即可通关。

该关复用经典攻击判定，只新增本关的照明线索、角色外观和世界内容。

### 4.3 25 岁：超市取证

- 明亮超市中设置低货架、岛台、活动区和底部收银撤离点。
- 出轨情侣分别巡逻，每局随机触发 5～6 次亲吻或拥抱事件。
- 目标警戒时拥有视线锥；玩家在无遮挡情况下停留会增加警戒值。
- 警戒值满后本局失败。
- 目标处于互动状态、取景无遮挡且进入有效拍摄范围时，拍照成功。
- 收集 4 张照片后撤离点由红色变为绿色；玩家抵达撤离点才通关。
- 普通攻击只用于制造短暂声响和疏散挡路人群，不伤害目标。

### 4.4 27 岁：躲黑锅

- 开放办公室中有普通职员、随机巡逻老板和不断坠落的黑锅。
- 黑锅落地前显示 0.5 秒红圈预警。
- 黑锅命中玩家扣除一点生命，短暂无敌；生命归零或超时失败。
- 老板免疫黑锅，且黑锅生成点尽量避开老板，避免错误暗示。
- 玩家找到老板并一拳命中后立即通关，不设置老板血条或多次攻击。
- 随时间推进缩短黑锅间隔并提高同时存在数量。

### 4.5 30 岁：爆金币还贷

- 工业场景四角设置不同外形的债务冲压机，边缘传送带会推动实体。
- 冲压机循环经历待机、预警、砸落和恢复四种状态。
- “打”只令路人短暂硬直，不会直接消灭路人。
- “推”把面前硬直中的路人向角色朝向强制位移。
- 路人被推进冲压区并砸中后爆出金币，金币自动计入进度。
- 玩家被任意冲压机命中立即失败。
- 金币达到 100 后通关；超时且未完成则失败。

## 5. 手机横屏设计

### 5.1 方向状态

- 视口高度大于宽度时判定为竖屏。
- 竖屏覆盖全屏旋转提示，并暂停当前关卡体验、音频和计时。
- 切回横屏后移除提示并恢复原状态。
- 切换浏览器后台时同样暂停，避免计时和机关在不可见时继续运行。
- 方向变化只触发一次状态迁移，不重复调用暂停或恢复。

### 5.2 安全区域与布局

- 顶部信息和底部控制统一叠加设备安全区域。
- 左下摇杆和右下动作区使用视口短边计算尺寸，并设置最小、最大值。
- 超宽屏限制信息条最大宽度，避免内容横向分散。
- 矮屏压缩顶部信息高度和按钮间距，保证游戏画面仍有足够可视区域。
- 拍照、推等扩展按钮沿主按钮左上方弧形排列。
- 所有触控按钮保留足够命中面积，视觉图标可以小于真实触控区域。

### 5.3 触控与性能

- 支持左手持续拖动摇杆时，右手同时按动作键。
- 使用指针编号分别跟踪摇杆与动作输入，避免第二根手指抢占摇杆。
- 禁止页面滚动、缩放和系统长按菜单干扰游戏。
- 失焦、暂停和方向切换时清空所有活动输入，避免角色持续移动。
- 限制设备像素比、粒子数量、动态光源数量和同时存在的机关数量。
- 窗口尺寸变化后更新渲染尺寸、镜头比例和触控布局。

## 6. 数据流与异常处理

### 6.1 通关数据流

```text
关卡报告成功
→ 结算模块显示阶段文案
→ 进度模块记录当前关卡
→ 根据主线顺序计算下一个可玩节点
→ 返回时间线并播放解锁反馈
```

关卡只报告成功、失败和统计信息，不自行操作主线存档。

### 6.2 生命周期

- 进入新关卡前释放上一关的事件、界面、场景对象和音频。
- 独立关卡的所有监听通过宿主资源域登记。
- 方向暂停不销毁关卡；离开关卡才执行释放。
- 某关加载失败时显示可返回时间线的错误界面，不污染其他关卡。

## 7. 测试与验收

### 7.1 自动测试

- 元数据校验：主线年龄合法、番外无年龄、顺序稳定。
- 进度测试：首关默认解锁、成功解锁下一关、失败不解锁、重玩不重复推进、损坏存档可恢复。
- 分组测试：六关进入主线，两关进入番外。
- 生命周期测试：三种独立玩法均能挂载、开始、更新、暂停、恢复和释放。
- 关卡规则测试：拍照次数与撤离、老板一拳、打后推、金币目标及失败条件。
- 输入测试：多指触控、方向切换清理输入、横屏恢复。
- 架构测试：关卡间无互相导入，共享模块无具体关卡判断。

### 7.2 浏览器验收

- 竖屏显示旋转提示且计时停止。
- 横屏恢复后操作正常。
- 小尺寸横屏、带安全区域设备、超宽屏和桌面尺寸均无控件遮挡。
- 摇杆与动作键可同时操作。
- 六关可按顺序解锁并完成。
- 番外可独立进入且不改变主线进度。

### 7.3 完成标准

- `npm test` 全部通过。
- `npm run build` 成功。
- 浏览器完成主线、番外、横竖屏和关键触控流程验证。
- 每个提交功能完整，提交说明使用中文。

## 8. 实施顺序

1. 先完成并提交元数据协议、进度存储、时间线和手机方向协调。
2. 调整现有四关分组，其中宿舍与图书馆进入主线，承天寺与血月进入番外。
3. 分别实现并测试鹅腿夜市、超市、办公室和冲压工厂。
4. 完成阶段过场与主线结局。
5. 执行全量测试、构建和浏览器验收，再提交最终代码。
