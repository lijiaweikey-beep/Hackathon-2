# 独立玩法关卡运行时设计

## 目标

将每个关卡提升为可独立开发、运行和销毁的小游戏模块。新增关卡可以拥有完全不同的玩法、输入方式、角色系统、镜头、界面和样式，同时不修改共享运行时、现有经典玩法系统或其他关卡目录。

现有四个关卡继续使用经典玩法适配器，玩法数值、操作手感、画面和结算表现保持不变。

## 当前限制

现有垂直切片已经隔离关卡场景、角色、规则、动画、音效和样式文件，但运行控制权仍然属于共享层：

- 游戏循环固定更新共享角色、战斗、界面和特效系统。
- 输入控制器固定提供移动与攻击。
- 界面控制器固定提供任务、抬头界面、暂停和结果结构。
- 关卡动作依赖中央动作白名单。
- 关卡样式虽然分文件保存，仍然处于页面全局样式环境。

因此，当前结构适合相同核心玩法的内容关卡，不足以承载玩法完全不同的小游戏。

## 架构原则

### 1. 共享外壳只管理应用级流程

共享外壳保留：

- 选关和关卡发现。
- 游戏阶段与会话。
- 渲染器和画布。
- 帧时钟。
- 音频恢复与基础音效。
- 结果持久化。
- 关卡资源域和异常隔离。
- 加载、退出和切换关卡。

共享外壳不再假定关卡具有玩家、非玩家角色、攻击、命中、冷却或固定抬头界面。

### 2. 关卡运行时拥有完整玩法

关卡可通过 `extensions.createExperience(host)` 创建独立运行时：

```js
export function createExperience(host) {
  return {
    presentation: "standalone",
    mount() {},
    start() {},
    update(deltaSeconds) {},
    pause() {},
    resume() {},
    handleInput(input) {},
    getResultStats() {},
    dispose() {},
  };
}
```

必需方法：

- `mount()`：创建场景、界面和输入订阅。
- `start()`：开始本局玩法。
- `update(deltaSeconds)`：执行本关卡每帧逻辑。
- `dispose()`：释放关卡直接持有的状态。

可选方法：

- `pause()`：响应暂停。
- `resume()`：响应恢复。
- `handleInput(input)`：处理共享外壳转发的抽象输入。
- `getResultStats()`：向共享结果界面提供统计信息。
- `render()`：需要自定义镜头或渲染顺序时接管渲染。
- `showResult(result)`：独立玩法自行显示结算界面。

`presentation` 支持：

- `"classic"`：使用现有任务、抬头和结果界面。
- `"standalone"`：关卡拥有自己的界面根节点和样式隔离区。

### 3. 经典玩法作为兼容适配器

没有声明 `extensions.createExperience` 的现有关卡，由 `createClassicExperience` 包装：

- 继续创建共享角色、战斗和特效系统。
- 继续使用现有任务、抬头、暂停和结果界面。
- 继续使用现有关卡动作和冻结能力上下文。
- 将原有固定帧更新顺序封装在经典适配器内部。

通用游戏循环只调用当前运行时，不再直接识别角色、战斗或界面系统。

### 4. 运行时管理器

`createExperienceManager` 是共享外壳与关卡运行时之间的唯一入口：

```js
const manager = createExperienceManager({
  createClassicExperience,
  createStandaloneHost,
});

manager.load(definition);
manager.mount();
manager.start();
manager.update(deltaSeconds);
manager.pause();
manager.resume();
manager.dispose();
```

职责：

- 根据关卡定义选择独立运行时或经典适配器。
- 同一时间只允许一个活动运行时。
- 加载新关卡前销毁旧运行时和资源域。
- 捕获运行时异常，清理资源并通知应用外壳。
- 向游戏循环暴露统一生命周期。

## 独立关卡宿主能力

`host` 是冻结的能力对象：

```js
{
  definition,
  scope,
  time,
  rendering,
  surface,
  input,
  audio,
  flow,
  storage,
  random,
}
```

### `time`

- `getPhase()`：读取当前游戏阶段。
- `getTotal()`：读取本局累计时间。

### `rendering`

- `THREE`：三维引擎命名空间。
- `canvas`：共享画布。
- `renderer`：共享渲染器，只读引用。
- `createScene()`：创建带清理登记的场景。
- `createCamera(options)`：创建关卡自己的镜头。
- `render(scene, camera)`：使用关卡指定镜头渲染。
- `disposeScene(scene)`：释放场景几何体、材质和非缓存纹理。

独立关卡不得创建第二个渲染器。

### `surface`

独立界面使用浏览器原生样式隔离根节点：

- `root`：关卡界面根节点。
- `setContent(html)`：设置关卡界面结构。
- `setStyles(cssText)`：设置只在该关卡界面内生效的样式。
- `clear()`：清空界面和样式。

经典关卡继续使用现有关卡视图宿主，以保持共享抬头界面主题能力。

### `input`

- `listen(target, type, listener, options)`：订阅原始输入，自动登记清理。
- `emit(action)`：向当前运行时发送抽象输入。
- `windowTarget`：浏览器窗口只读引用。
- `canvas`：画布只读引用。

独立关卡激活时，经典移动与攻击处理停止生效。退出关卡后，输入订阅由资源域统一移除。

### `flow`

- `start()`：将会话进入游戏阶段。
- `pause()`：进入暂停阶段。
- `resume()`：恢复游戏阶段。
- `finish({ won, failMessage, stats })`：进入结算阶段。
- `leave()`：返回选关界面。

独立关卡不得直接写入共享会话阶段。

### `storage`

- `get(key, fallback)`：读取关卡命名空间下的数据。
- `set(key, value)`：写入关卡命名空间下的数据。

键名自动添加关卡标识前缀，避免不同关卡覆盖数据。

## 游戏循环

通用循环只执行：

```text
读取帧间隔
→ 判断当前会话阶段
→ 调用活动运行时对应生命周期
→ 调用运行时渲染
```

经典角色、战斗、顿帧、粒子和抬头界面更新全部移入 `createClassicExperience`。独立关卡可以完全不创建这些系统。

## 界面与样式隔离

### 选关界面

选关卡片配色由关卡定义数据提供，不依赖加载关卡运行时样式。

### 经典关卡

现有经典样式由经典适配器在关卡激活期间加载，退出时卸载。血月关卡仍可通过主题属性改变共享抬头界面。

### 独立关卡

独立关卡界面挂载在浏览器原生隔离根节点中。其样式不能选择或覆盖共享选关页、其他关卡界面或共享抬头界面。

三维画布仍由共享外壳持有，独立界面根节点覆盖在画布上方。

## 动作与事件

中央动作白名单仅服务经典玩法适配器。独立关卡的内部动作、状态机和事件都保留在关卡目录中，不需要登记到 `actions.js`。

共享外壳与独立运行时之间只传递生命周期、输入和流程控制，不传递关卡内部动作名称。

## 错误和清理

- 创建运行时失败：销毁刚创建的资源域，回到选关界面并报告关卡标识。
- 每帧更新失败：立即停止运行时，依次执行运行时 `dispose()` 和资源域清理。
- 重复销毁：不得重复执行资源清理。
- 关卡切换：先销毁旧运行时，再创建新运行时。
- 输入、计时器、界面根节点和样式节点必须登记到资源域。
- 场景资源由渲染能力统一释放。

## 目录约定

独立关卡仍然只修改自己的目录：

```text
src/levels/<关卡标识>/
├── definition.js
├── createExperience.js
├── state.js
├── input.js
├── world.js
├── view.js
├── styles.css
├── audio.js
├── constants.js
└── tests 对应文件
```

不是所有文件都必须存在，关卡只创建实际需要的文件。

## 测试与验收

必须增加一个完全独立的样例关卡，证明它：

- 不导入共享角色系统。
- 不导入共享战斗系统。
- 不导入共享输入控制器。
- 不使用中央关卡动作。
- 拥有自己的输入处理、每帧更新、界面和隔离样式。
- 可以开始、暂停、恢复、结算和销毁。
- 退出后不残留事件监听、界面或样式。

架构测试必须保证：

- 新增独立关卡只添加关卡目录和对应测试即可被发现。
- 通用游戏循环不包含角色、战斗或具体界面更新调用。
- 共享运行时不包含具体关卡标识。
- 关卡之间禁止互相导入。
- 独立样式不能泄漏到共享页面。
- 现有经典关卡完整测试和生产构建继续通过。

## 迁移顺序

1. 扩展关卡契约，支持独立运行时定义。
2. 建立运行时管理器与冻结宿主能力。
3. 将通用游戏循环改为运行时委托。
4. 提取经典玩法适配器，保持现有四关行为。
5. 建立独立界面隔离区和资源化输入订阅。
6. 建立独立样例关卡和架构防回退测试。
7. 更新多人并行开发指南并执行全量验证。

## 不在本次范围

- 不重写现有四个经典关卡的玩法。
- 不恢复或接入休眠双人模式。
- 不引入新的第三方依赖。
- 不建立跨关卡事件总线。
- 不允许多个关卡同时运行。
- 不为未来未知需求预建脚本语言或可视化编辑器。
