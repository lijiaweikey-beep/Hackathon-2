# 超市取证完整玩法重构设计

> 日期：2026-07-29
>
> 状态：用户已确认

## 目标

25 岁“超市取证”只在核心玩法上区别于前置关卡。角色移动、转向、步行动画、
碰撞、避障和角色分离必须复用共享实现；本关只独立维护目标事件、拍照取证、
警戒与撤离规则。手机横屏不作为本轮验收重点。

## 架构

### 共享角色行为

- 玩家和所有非玩家角色改为标准角色对象，不再只保存模型根节点。
- 独立体验直接组合 `createActorSystem`，沿用速度、输入平滑、朝向、步行动画、
  漫游、避障和角色分离。
- 货架、收银台和墙体统一登记为障碍物，所有角色经过同一碰撞解析。

### 目标事件

目标情侣使用本关状态机：

1. 分散移动到合法通道点。
2. 步行靠近同一个互动点。
3. 面向彼此互动并开放一次拍摄机会。
4. 成功拍摄或机会结束后再次分散。

目标只能通过共享导航移动，不允许瞬移或直接写入环形轨迹。每次互动拥有唯一
事件编号，同一事件最多生成一张有效证据。

### 拍照取证

成功照片同时满足：

- 目标正在互动。
- 两名目标都在玩家前方取景角度内。
- 两名目标都在有效距离内。
- 玩家与两名目标之间都没有货架或柜台遮挡。
- 当前互动事件尚未拍摄。

失败拍摄必须显示具体原因。成功拍摄播放举相机、对焦、快门闪光和证据卡片动画，
证据卡明确显示当前进度。

### 警戒

警戒表示目标对玩家的怀疑：

- 玩家靠得过近、无遮挡且处于目标视野内时增长。
- 拉开距离或利用货架遮挡时下降。
- 互动期间同样计算警戒，避免拍摄窗口反而成为绝对安全时间。
- 界面常驻说明增长、下降和满值失败的规则，并用文字显示安全、注意和危险状态。

### 撤离

四次不同互动的有效证据收集完成后开放中央收银通道。玩家必须进入实际出口触发
区域才能通关，不能只依赖单个坐标越界。

## 文件边界

- `actors.js`：创建标准玩家和非玩家角色。
- `world.js`：场景、障碍物、合法互动点、视线遮挡和出口触发区域。
- `targetSequence.js`：目标情侣状态机。
- `rules.js`：拍照、唯一事件、失败原因和撤离规则。
- `createExperience.js`：组合各模块、输入、界面反馈和结算。
- `styles.css`：警戒说明、取景状态、快门和证据卡动画。

## 验收

- 玩家移动手感和步行动画与前置关卡同源。
- 玩家、目标和顾客不会穿过货架、收银台或彼此重叠。
- 普通顾客持续漫游，目标完整执行分散、靠近、互动、离开的循环。
- 只有两名目标都进入取景条件时才能拍摄，同一次互动不能重复计数。
- 成功与失败拍照都有明确动画和文字反馈。
- 警戒用途、变化条件和失败后果无需猜测。
- 四张不同有效证据后进入中央绿色出口才能通关。
- 相关自动化测试、全量测试、生产构建和实际浏览器游玩验证通过。
