# 超市取证视觉统一设计

> 日期：2026-07-29
>
> 状态：已确认方案一

## 1. 目标

让 25 岁“超市取证”在视觉上与 19、21、23 岁关卡属于同一款游戏，同时保留
现有潜行、警戒、拍照、收集四张证据和收银区撤离规则。

验收重点：

- 人物改为前面关卡一致的低多边形人物，不再使用胶囊身体。
- 场景从纯色方块升级为低多边形超市，货架、商品、收银台和照明层次清楚。
- 镜头、阴影、色彩与前三关保持一致的俯视立体感。
- 抬头信息、摇杆、拍照按钮、简报和结算统一为主线关卡的深色玻璃质感。
- 手机横屏下信息和操作按钮完整可见。

## 2. 已选方案

采用“保留独立玩法，重做视觉层”：

- 不把超市改造成经典关卡，不修改共享战斗或角色系统。
- 独立体验继续管理移动、视线遮挡、互动机会、警戒和撤离。
- 把场景搭建与人物创建从 `createExperience.js` 拆出，降低文件耦合。
- 复用共享低多边形人物工厂和调色板，但不依赖任何其他关卡目录。

未采用方案：

- 完全迁移到经典关卡：会迫使拍照和警戒规则适配攻击系统，改动大且风险高。
- 只改颜色和界面：无法解决胶囊人物与简陋方块场景的核心割裂。

## 3. 文件边界

### 3.1 `actors.js`

只负责创建低多边形人物：

- 玩家使用橙色外套，保持主角辨识度。
- 目标情侣使用粉色与蓝色服装，并保留成对视觉关系。
- 普通顾客使用共享人物调色板循环生成。
- 返回的角色对象只暴露体验循环需要的 `group`。

### 3.2 `world.js`

只负责创建低多边形超市场景：

- 米灰色地砖和暖白墙面组成明亮基础。
- 六组货架保留原碰撞尺寸，避免改变路线和遮挡规则。
- 每组货架增加层板、立柱和多色商品块，形成可辨识的商品陈列。
- 底部收银通道加入柜台、出口灯箱和红绿状态灯。
- 顶部增加规则排列的灯带，配合环境光、主光和阴影形成前三关的立体感。
- 返回 `scene`、`camera`、`shelves`、`exit`、`player` 和人物集合。

### 3.3 `createExperience.js`

只保留玩法编排：

- 挂载世界和界面。
- 处理移动、碰撞、情侣巡逻与互动。
- 计算遮挡、距离、警戒、拍照和撤离。
- 管理暂停、恢复、结算和资源释放。

不改变以下数值：90 秒、4 张照片、5～6 次机会、警戒增长与衰减速度、有效距离。

### 3.4 `styles.css`

视觉对齐全局主线：

- 深色半透明信息条、细边框、轻模糊和小圆角。
- 摇杆使用青绿色半透明旋钮，尺寸与经典关卡一致。
- 拍照按钮沿用圆形大触控区，准备状态用青绿色脉冲，不改变点击范围。
- 简报与结算使用统一面板层级和按钮样式。
- 横屏高度不超过 480 像素时压缩间距，保证开始按钮和控制区可见。

## 4. 数据流

```text
独立体验挂载
→ world 创建低多边形超市和角色
→ 玩法循环更新角色位置
→ rules 计算拍照、失败和出口状态
→ world 更新出口灯光
→ 隔离界面更新照片、警戒和倒计时
```

视觉模块不读取或修改规则状态，只接受体验层传入的位置与出口状态。

## 5. 测试与验收

- 人物测试确认玩家、情侣和顾客都使用低多边形身体结构。
- 世界测试确认六组货架、商品陈列、收银区和出口状态资源存在。
- 原有规则与生命周期测试必须继续通过，证明玩法未改变。
- 架构测试必须确认超市不导入其他关卡目录。
- 全量自动测试与生产构建通过。
- 浏览器横屏验收超市简报、实际游戏画面、摇杆、拍照按钮和出口提示。
