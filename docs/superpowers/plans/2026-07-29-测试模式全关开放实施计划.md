# 测试模式全关开放实施计划

> **执行要求：** 使用 `superpowers:executing-plans` 逐项实现，并以测试先行。

**目标：** 本地开发时六个主线关卡全部可直接进入，正式构建继续逐关解锁。

**架构：** 解锁策略仍由 `createStoryProgress` 统一提供，通过只读的
`unlockAll` 参数切换测试策略。应用入口仅负责把开发环境标志传入进度模块，
界面和选关流程继续调用现有 `isUnlocked()`，不增加第二套判断。

**技术栈：** 原生 JavaScript、Vite、Node.js 测试运行器。

## 全局约束

- 测试模式只跳过入口锁定，不写入虚假通关记录。
- 未知关卡标识在任何模式下都不能解锁。
- 正式模式的逐关解锁行为必须保持不变。
- 不新增依赖，不修改任何具体关卡实现。

### 任务一：为人生进度增加全关开放策略

**文件：**

- 修改：`tests/progression/storyProgress.test.js`
- 修改：`src/progression/createStoryProgress.js`
- 修改：`src/runtime/createGameApplication.js`

**接口：**

- 输入：`createStoryProgress({ levels, storage, key, unlockAll })`
- 输出：`isUnlocked(id)` 在 `unlockAll === true` 时对所有已注册主线返回
  `true`，未知标识仍返回 `false`。

- [ ] **步骤一：编写失败测试**

```js
test("测试模式开放所有已注册主线但不伪造通关", () => {
  const progress = createStoryProgress({
    levels,
    storage: createMemoryStorage(),
    key: "story",
    unlockAll: true,
  });

  assert.deepEqual(
    levels.map(({ id }) => progress.isUnlocked(id)),
    [true, true, true],
  );
  assert.equal(progress.isUnlocked("missing"), false);
  assert.deepEqual(progress.getCompletedIds(), []);
});
```

- [ ] **步骤二：运行定向测试并确认失败**

运行：`npm test -- tests/progression/storyProgress.test.js`

预期：新测试因后续主线仍被锁定而失败。

- [ ] **步骤三：实现最小解锁策略**

先拒绝未知标识，再在 `unlockAll` 为真时返回 `true`，否则执行原有逐关逻辑。
