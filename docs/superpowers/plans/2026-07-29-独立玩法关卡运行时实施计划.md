# 独立玩法关卡运行时实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让每个新关卡可以独立拥有玩法、输入、循环、镜头、界面和隔离样式，且无需修改共享运行时。

**Architecture:** 新增统一体验运行时契约和管理器，通用循环只委托当前体验。现有四关由经典体验适配器继续使用角色、战斗、特效和共享界面；全新关卡通过独立宿主获得渲染、输入、隔离界面和流程能力。

**Tech Stack:** JavaScript 模块、Three.js、Vite、Node.js 内置测试运行器、浏览器原生隔离根节点。

## Global Constraints

- 保持现有四个关卡玩法、数值、操作和画面不变。
- 不恢复或接入 `src/modes/duel/`。
- 不增加第三方依赖。
- 保留用户现有的 `package-lock.json` 未提交改动。
- 每项生产改动先写失败测试，再实现最小代码。
- 每项完整功能使用中文提交信息。
- 独立关卡不得依赖共享角色、战斗、固定输入和固定界面系统。

---

## 文件结构

- `src/runtime/createExperienceManager.js`：加载、验证、委托和销毁当前体验。
- `src/runtime/createExperienceHost.js`：创建冻结的独立体验能力宿主。
- `src/runtime/createClassicExperience.js`：封装现有固定玩法帧流程。
- `src/runtime/createGameLoop.js`：只处理阶段、帧间隔和体验委托。
- `src/ui/createLevelSurface.js`：创建浏览器原生样式隔离界面。
- `src/systems/createScopedInput.js`：登记并自动释放关卡输入监听。
- `src/levels/levelContract.js`：允许 `createExperience` 独立玩法扩展。
- `src/levels/registry.js`：以内联文本发现样式，不再全局注入。
- `tests/fixtures/standalone-level/`：完全不依赖经典玩法系统的可运行样例。
