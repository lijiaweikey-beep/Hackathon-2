# 关卡目录与界面边界 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让首页只消费“可见关卡目录”，用稳定关卡标识选关，并把已有的任务弹窗、目标预览和决斗规则拆分正式纳入模块边界。

**Architecture:** `levelRegistry` 负责关卡发现、排序、可见性和标识到旧数组下标的兼容映射；首页只消费 `visible`，不再识别具体玩法类型。纯展示文案由 `levelCardModel` 生成，DOM 渲染仍保留在现有入口，避免为单一页面引入额外控制器。

**Tech Stack:** JavaScript ES Modules、Three.js、Vite、Node.js 内置测试运行器

## Global Constraints

- 新关卡通过 `src/levels/<level-id>/definition.js` 自动注册，首页不得维护关卡白名单。
- 隐藏关卡由关卡描述的 `hidden` 字段控制，首页不得判断 `duelMode`。
- 首页选关使用稳定 `id`，旧运行时数组下标只允许在注册中心兼容边界内换算。
- 不新增运行时依赖。
- 每个提交使用中文提交信息，且提交时功能完整可运行。

```js
export function createLevelCardModel(level, { npcCount }) {
  const difficulty = level.difficulty >= 4
    ? { label: "困难", className: "hard" }
    : [
        { label: "", className: "" },
        { label: "简单", className: "easy" },
        { label: "经典", className: "classic" },
        { label: "推荐", className: "recommended" },
      ][level.difficulty] ?? { label: "", className: "" };
  return {
    description: typeof level.cardDesc === "function"
      ? level.cardDesc({ npcCount })
      : level.cardDesc,
    difficulty,
  };
}
```
